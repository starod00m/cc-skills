# Скиллы Claude Code для пайплайна «от задачи до MR»

Это снимок моего личного набора скиллов и агентов для Claude Code, на котором я веду задачу от
постановки до merge request. Репозиторий не поддерживается и обновляться не будет. Копировать его
как есть смысла мало: скиллы заточены под мой процесс, мои конвенции и мой стек (GitLab, Jira,
Codex CLI, tmux, Emacs). Берите подход, разбирайте, что вам подходит, и адаптируйте под себя.

## Пайплайн

Цепочка: брейншторм → план → реализация → ревью → ручной тест → MR. Каждый шаг заканчивается
подсказкой, какую команду запускать следующей.

| Этап | Скилл | Что делает |
|---|---|---|
| Сквозной контекст задачи | `st-ticket-workflow` | Ведёт `docs/tickets/<KEY>.md` — общую память между сессиями и агентами: разведка по тикету при старте, трекер задач «до мержа», решения и отброшенные подходы |
| Прожарка / мозгоштурм | `st-grill` | Интервью по дизайну раундами, по ходу пишет глоссарий и ADR; заканчивается жёстким стопом, где пользователь выбирает следующий шаг |
| | `st-spec-create` | Собирает спеку из уже состоявшегося разговора в `docs/plans/<yyyymmdd>-<slug>-spec.md`, без повторного интервью |
| Изоляция | git worktree | Отдельного скилла нет: `st-plan-create` первым шагом уводит сессию в worktree через `EnterWorktree`, `st-plan-exec` проверяет, что уже в нём, и при необходимости создаёт |
| Написание плана | `st-plan-create` | Интерактивно пишет план реализации в `docs/plans/` — вопросы по одному, выбор подхода, авторевью агентом `plan-review` и Codex с триажем, аннотация, коммит |
| | `st-plan-annotate` | Открывает план (или спеку) в `$EDITOR` в tmux-сплите, применяет правки пользователя и повторяет, пока правки не закончатся |
| Выполнение плана | `st-plan-exec` | Автономно исполняет план: по сабагенту на таск, чекбоксы плана как источник правды, журнал решений и отклонений, затем полный цикл `st-review`, статистика и архивация плана |
| ИИ-ревью | `st-review` + агенты | Итеративное ревью ветки: Claude-агенты находят замечания, валидатор отсеивает ложные, фиксер правит и коммитит, пока итерация не пройдёт без замечаний; затем тот же цикл с Codex как вторым взглядом |
| ИИ-тестирование | `st-manual-test` | QA-прогон изменений на реальных данных: карта покрытия автотестами, тест-план без дублей юнитов, сверка плана и механики прогона с Codex, отчёт PASS / FAIL / UNVERIFIED |
| Ручное ревью | `st-git-review` | Обрабатывает аннотации из `.review/*.md`: `FIX` применяет, `ASK` обсуждает по одному, после коммита правок гоняет их через `quality-reviewer` и Codex |
| Финализация и MR | `st-branch-finalize` | Ребейз на целевую ветку, чистка истории в логические коммиты, проверка, что доки описывают состояние после мержа, прогон тестов и линтера |
| | `st-mr-create` | Полный цикл до MR в GitLab: финализация ветки, коммит оставшихся изменений, пуш, описание по итоговому diff, `glab mr create` |

## Агенты

Агенты — сабагенты Claude Code с узкой специализацией и своим чеклистом. Сами по себе их никто не
зовёт, их запускают скиллы:

| Агент | Что проверяет | Кто вызывает |
|---|---|---|
| `plan-review` | План до исполнения: постановка, покрытие спеки, архитектура, лишняя спецификация, тесты | `st-plan-create` |
| `quality-reviewer` | Баги, безопасность, достигнута ли цель плана | `st-review` (каждая итерация), `st-git-review` |
| `testing-reviewer` | Недостающие, фальшивые и лишние тесты | `st-review` |
| `documentation-reviewer` | Чего не хватает в доках и соблюдены ли правила автора в написанной прозе | `st-review` |
| `spec-reviewer` | То ли построили, что просила спека | `st-review`, если спека есть |
| `architecture-reviewer` | Системные решения: слои, границы модулей, режимы запуска | `st-review`, первая итерация |
| `simplification-reviewer` | Переусложнение: лишние абстракции, преждевременные обобщения | `st-review`, первая итерация |

Во второй фазе `st-review` тела этих же агентов уходят в Codex как роли.

## Установка

Скопируйте каталоги из `skills/` в `.claude/skills/` проекта или в `~/.claude/skills/`, файлы из
`agents/` — в `.claude/agents/` проекта или в `~/.claude/agents/`. Скрипт `st-plan-annotate`
вызывается через `${CLAUDE_SKILL_DIR}`, поэтому каталог скилла копируйте целиком.

## Зависимости

| Что | Кому нужно |
|---|---|
| `git` | всем |
| [`glab`](https://gitlab.com/gitlab-org/cli), авторизованный в вашем GitLab | `st-mr-create`, `st-branch-finalize`, разведка в `st-ticket-workflow` |
| [Codex CLI](https://github.com/openai/codex) | вторая фаза `st-review`, авторевью в `st-plan-create`, сверки в `st-manual-test`, кросс-ревью в `st-git-review`; без него эти шаги пропускаются с пометкой |
| tmux с подключённым клиентом, `$EDITOR`, `python3` | `st-plan-annotate` |
| [plannotator](https://github.com/backnotprop/plannotator) | опционально — альтернативный способ аннотации в `st-spec-create` и `st-plan-create` |
| Скиллы `grilling`, `domain-modeling`, `resolving-merge-conflicts` из [mattpocock/skills](https://github.com/mattpocock/skills) | `st-grill` (первые два), `st-branch-finalize` (конфликты при ребейзе) |
| Emacs с хелпером, который пишет `.review/*.md` | `st-git-review`; хелпер в набор не входит, формат файла описан в самом скилле |
| MCP-серверы Jira, Confluence, Mattermost | разведка в `st-ticket-workflow`; без них соответствующие источники будут «не прочитаны» |

## Конвенции, которые стоит заменить на свои

Это договорённости моей команды, а не требования скиллов:

- заголовок MR `[KEY] описание` с ключом тикета — `st-mr-create`;
- сообщения коммитов на русском (`st-mr-create`, фиксер в `st-review`, `st-git-review`, архивация плана
  в `st-plan-exec`);
- имена веток с семантическим префиксом `feat/`, `fix/`, `refactor/`, `chore/` и английским slug —
  `st-plan-create`, `st-plan-exec`, `st-ticket-workflow`;
- дока тикета в `docs/tickets/<KEY>.md`, планы и спеки в `docs/plans/`.

Гейт `st-ticket-workflow` («пока в „До мержа“ есть открытые пункты, MR не создаём») в этом снимке
держится только на инструкции скилла. У меня его подпирали хуки Claude Code, в набор они не вошли:
если гейт нужен жёстким, напишите PreToolUse-хук под свой процесс.
