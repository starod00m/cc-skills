# st-manual-test — шаблоны тест-плана и отчёта

## Тест-план (`/tmp/qa-test-plan-<timestamp>.md`)

```markdown
# QA Test Plan: <название фичи>

**Ветка:** <имя ветки>
**Дата:** <дата>
**Изменённые модули:** <список>

## Доступные инструменты тестирования

- <инструменты, стенды, данные>

## Недостающие ресурсы

- <чего нет у агента: данные, сервисы, доступы, эталонные значения — конкретно>
- Либо: «Все необходимые ресурсы доступны»

## Тест-кейсы

### Группа 1: <например «Основной сценарий»>

- [ ] **TC-001: <название>**
  - Предусловия: …
  - Шаги: …
  - Ожидаемый результат: …
  - Как проверить: <конкретная команда / запрос / действие>
  - Критерий PASS: <что должно наблюдаться в выводе>
  - Чего не ловят автотесты: <факт, который добывает этот кейс сверх карты покрытия>

- [ ] **TC-002: …**

### Группа 2: <граничные случаи>

### Группа 3: <регрессия — существующее не сломано>

## Не покрытые тест-кейсами user stories

- <story из спеки без кейса и почему>, либо «все покрыты»

## Выброшено как дубль автотестов

| Проверка | Уже ловит |
|---|---|
| <что напрашивалось проверить> | <файл:строка, имя теста> |
```

## Отчёт (в консоль)

```markdown
# QA Test Report

**Ветка:** <имя ветки>
**Дата:** <дата>
**Статус:** PASS | FAIL | PARTIAL

## Сводка

| Метрика | Значение |
|---|---|
| Всего тестов | N |
| PASS | N |
| FAIL | N |
| UNVERIFIED | N |
| SKIPPED | N |

## Результаты по группам

### <Группа 1>

| # | Тест-кейс | Статус | Комментарий |
|---|---|---|---|
| TC-001 | <название> | PASS | Проверено: <что наблюдалось> |
| TC-002 | <название> | FAIL | см. проблему #1 |
| TC-003 | <название> | UNVERIFIED | Нужно: <что требуется> |

## Найденные проблемы

### Проблема #1: <кратко>

- **Severity:** critical | major | minor
- **Тест-кейс:** TC-002
- **Симптом:** <что наблюдается>
- **Ожидалось:** <что должно быть>
- **Фактически:** <конкретный вывод>
- **Root cause:** <файл:строка — причина>
- **Воспроизведение:** <команда>

## Непроверенные тест-кейсы

| # | Тест-кейс | Что нужно для проверки |
|---|---|---|
| TC-003 | <название> | <ресурс / данные / доступ> |

## Границы доказанного

Что прогон не доказывает из-за заглушек, фейков, узких моделей отказа, проверок на уровне модуля
вместо сквозного пути (по итогам Фазы 4).

## Сверка с Codex

- Выброшено как дубль автотестов: N кейсов (Фаза 2.5)

- Аннулировано и перегнано после сверки механики: N (Фаза 4)
- Отклонено с обоснованием: <замечания, не подтвердившиеся по коду>

## Заключение
```
